# Competing Information Diffusion in Crisis Communication Networks

Wolfram Mathematica implementation of a discrete-time network model for
competing misinformation and official information in crisis communication.

The model combines:

- ordinary agents and highly connected media/institutional nodes;
- delayed activation of an official information campaign;
- misinformation and official-information diffusion through a communication
  network;
- residence-time-dependent resistance to competing information;
- stochastic simulation and run-level outcome metrics.

The repository accompanies the article:

> **A Mathematical Simulation Model of Competing Information Diffusion in Crisis Communication Networks**  
> Aleksandar Hatzivelkos

## Source modules

The implementation is divided into several Wolfram Language modules.

### `01_TypesAndValidation.wl`

Defines model constants, parameter validation, and network specification
validation.

### `02_Networks.wl`

Generates communication networks, assigns media/institutional nodes, and
constructs network data used by the simulation.

### `03_Initialization.wl`

Creates initial node states and selects initial misinformation sources.

### `04_Signals.wl`

Implements signal generation and aggregation across neighboring nodes.

### `05_UpdateRules.wl`

Implements the stochastic state-transition rules, including
residence-time-dependent transition probabilities and activation of the
official campaign.

### `06_SimulationCore.wl`

Runs individual simulations and stores the simulated state history.

### `07_Metrics.wl`

Computes time-series summaries and run-level outcome measures, including
misinformation prevalence, peak misinformation, clearance measures,
information-dominance time, and terminal misinformation trends.

### `09_Export.wl`

Provides export utilities for simulation results and experiment metadata.

## Demonstration notebook

The main entry point for new users is:

    notebooks/Demo_Simulation.nb

The notebook provides a small reproducible example of the computational
workflow. It:

1. loads the simulation modules;
2. defines a small communication network;
3. generates the network realization;
4. selects initial misinformation sources;
5. initializes node states;
6. runs one stochastic simulation;
7. computes selected outcome measures;
8. plots misinformation and official-information trajectories;
9. exports demonstration results.

The demonstration configuration is intentionally small so that it can be
executed quickly. It is designed to illustrate the model and software
workflow, not to reproduce the complete production experiments reported in
the article.

## Running the demonstration

Clone or download the repository and preserve its directory structure.

Open:

    notebooks/Demo_Simulation.nb

in Wolfram Mathematica and evaluate the notebook from the beginning.

The notebook automatically identifies the repository root relative to its own
location, so no absolute local paths need to be configured.

When executed successfully, the notebook writes:

    demo_output/
    ├── demo_time_series.csv
    ├── demo_run_metrics.csv
    └── demo_dynamics.png

The repository already contains reference versions of these files.

`demo_time_series.csv` contains the time evolution of the aggregate model
states.

`demo_run_metrics.csv` contains selected outcome measures for the
demonstration run.

`demo_dynamics.png` contains the corresponding visualization of misinformation
and official-information prevalence.

## Demonstration configuration

The supplied demonstration uses a small-world communication network with:

    Network size                  30
    Media/institutional nodes      3
    Agent connectivity k           4
    Media degree multiplier        3

The diffusion parameters are:

    Official-information strength c    0.45
    Misinformation strength d           0.35
    Official campaign delay tau         5
    Simulation horizon Tmax            40
    Initial misinformation sources      2

Fixed pseudorandom seeds are included in the notebook for network generation,
misinformation-source selection, and stochastic simulation.

Users can modify these parameters directly in the
`Demo configuration` section of the notebook.

## Model states

Each ordinary agent is in one of three states:

- `U` — uninformed;
- `M` — misinformed;
- `I` — informed.

Before the official campaign is activated, media/institutional nodes follow the
same state-transition rules as ordinary nodes.

At the campaign activation time `tau`, all media/institutional nodes become
permanent official-information spreaders and remain in state `I` thereafter.

Transition probabilities depend on neighboring signals and on the time already
spent in the current non-neutral state. This provides a stylized representation
of increasing resistance to competing information as a belief becomes more
established.

## Production experiments

The full experiments reported in the associated article are substantially more
computationally demanding than the demonstration notebook.

They include:

- response-delay experiments across multiple levels of
  official-information credibility;
- repeated stochastic simulations for each parameter configuration;
- robustness analysis across independently generated sparse, benchmark, and
  dense network realizations.

The production experiments were executed through parameterized simulation
runs and are not launched automatically by this repository.

Instead, the simulation outputs underlying the reported figures and tables are
provided in the accompanying Zenodo dataset:

> `[ZENODO DATASET LINK TO BE ADDED]`

This separation keeps the software repository compact while preserving access
to the data required to reproduce the reported numerical analyses.

## Data availability

The public dataset contains the experiment metadata, network specifications,
initial misinformation sources, run-level time series and outcome metrics,
aggregate summaries, and topology-experiment outputs required for the analyses
reported in the article.

Full node-by-node state-history files generated internally during the
production simulations are not included in the public dataset because they are
not required to reproduce the reported analyses and would substantially
increase the archive size.

See the `README_DATA.md` file included with the Zenodo dataset for a detailed
description of the archived data.

## Reproducibility

The code uses explicit pseudorandom seeds for network generation, initial
misinformation-source selection, and stochastic simulation.

The demonstration notebook has been tested from a fresh Mathematica kernel and
can be executed from beginning to end using the supplied repository structure.

The production dataset additionally records the seeds and parameter settings
used in the archived experiments.

The full production simulations require substantially more computation time
than the demonstration and are therefore provided as archived outputs rather
than being automatically regenerated by the public demonstration notebook.
